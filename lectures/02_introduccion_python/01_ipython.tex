    \section*{\textcolor{red}{\textit{Tipos de lenguajes}}}

    Anteriormente, vimos que las computadoras solo entienden el lenguaje binario, es decir, cadenas asociadas
    al alfabeto $\{0,1\}$. En particular, trabajamos con cadenas de 8 bits (bytes). A este lenguaje se le conoce 
    como \textit{lenguaje de máquina}. Sin embargo, a la hora de dar instrucciones a la computadora, resulta
    engorroso y propenso a errores tener que hacerlo con esas cadenas interminables de ceros y unos. 

    Para solucionar esto, el primer paso histórico fue la creación del \textit{lenguaje 
    ensamblador} (\textit{Assembly}). En lugar de escribir secuencias binarias, este lenguaje 
    utiliza nemónicos (instrucciones en texto corto como    \texttt{MOV}, \texttt{ADD} o 
    \texttt{JMP}) para representar directamente las operaciones del procesador. 

    Para que la computadora entienda estas instrucciones, se utiliza un \textbf{ensamblador} 
    (\textit{assembler}): un programa traductor que convierte el código escrito en lenguaje 
    ensamblador a su equivalente en lenguaje de máquina. Tanto el lenguaje de máquina 
    como el ensamblador son considerados \textit{lenguajes de bajo nivel}, pues están 
    directamente atados a la arquitectura física del procesador (por ejemplo, x86, ARM) y 
    requieren gestionar manualmente los registros de la CPU y las direcciones de memoria.

    Con el tiempo, para abstraerse del hardware y escribir programas portátiles y legibles, 
    se crearon los  \textit{lenguajes de alto nivel}. Existen numerosos lenguajes de alto nivel: 
    Python, Java, C, C++, JavaScript, Ruby, Swift, Visual Basic, Perl, .NET, Fortran, Pascal, 
    CUDA, entre otros. Aunque difieren en muchos detalles, 
    todos comparten la propiedad de tener sintaxis y semántica bien definidas y no ambiguas. 

    Dado que la computadora solo comprende el lenguaje de bajo nivel, 
    cuando escribimos un programa en un lenguaje de alto nivel debemos usar un traductor 
    para convertirlo a lenguaje de máquina. 
    Esto se realiza principalmente mediante dos esquemas:
    \textit{compilación} e \textit{interpretación}.

  \begin{itemize}
    \item \textbf{Lenguajes Compilados (ej. C, C++, Fortran):} 
    El programa fuente se pasa por un software llamado \textit{compilador} (gcc, gfortran), 
    el cual analiza todo el código y genera un archivo ejecutable binario 
    independiente (código de máquina nativo para una arquitectura específica). 
    \begin{itemize}
        \item \textit{Ventaja:} Ejecución extremadamente rápida y optimizada para el procesador.
        \item \textit{Desventaja:} Si se cambia el sistema operativo o la arquitectura, 
        se debe recompilar. Los errores se detectan antes de la ejecución.
    \end{itemize}

    \item \textbf{Lenguajes Interpretados (ej. Ruby, Python, JavaScript):} 
    Un programa denominado \textit{intérprete} lee el código fuente línea por línea y lo traduce e instruye 
    al procesador en tiempo real.
    \begin{itemize}
        \item \textit{Ventaja:} Alta portabilidad y facilidad de depuración durante el desarrollo.
        \item \textit{Desventaja:} Menor velocidad de ejecución, ya que el proceso de traducción ocurre 
        mientras el programa corre.
    \end{itemize}
\end{itemize}

\subsubsection*{El modelo híbrido de Python}
A diferencia de los lenguajes interpretados puros, Python no lee directamente el texto del código fuente 
en cada ejecución. En su lugar, utiliza un esquema de dos pasos:
\begin{enumerate}
    \item Traduce el archivo fuente (\texttt{.py}) a un código intermedio ejecutable 
    llamado \textit{Bytecode} (\texttt{.pyc}).
    \item La máquina virtual de Python (PVM) procesa y ejecuta dicho \textit{Bytecode}.
\end{enumerate}
Este enfoque permite combinar la flexibilidad de los lenguajes interpretados con una mejor
velocidad al reejecutar módulos ya procesados.

\section*{\textcolor{red}{\textit{¿Por qué Python?}}}

Si existen tantos lenguajes de programación y, además, los que son compilados como C, C++ o 
Fortran son más rápidos, ¿por qué aprender Python? 
Hay diferentes buenas respuestas para esto, un par radican en el hecho de que su sintaxis es simple, 
el software es libre y la comunidad que lo mantiene es muy grande. Así mismo, una serie de 
ventajas que presenta Python son:

\begin{enumerate}
    \item Python permite expresar conceptos matemáticos y físicos complejos con muy pocas 
    líneas de código. Su sintaxis es legible y carece de la sobrecarga de gestión manual 
    de memoria (como punteros o asignación explícita) presente en lenguajes como C++. 
    Esto permite a concentrarse en la \textit{física del problema} y no en el código.

    \item Python cuenta con un conjunto de librerías especializadas que cubren 
    prácticamente cualquier necesidad del análisis numérico y la modelación:
    \begin{itemize}
        \item \textbf{NumPy:} Manejo eficiente de vectores, matrices y álgebra lineal.
        \item \textbf{SciPy:} Solución de ecuaciones diferenciales, integración numérica, optimización y transformada de Fourier.
        \item \textbf{Matplotlib / Seaborn:} Visualización de datos, generación de gráficos de calidad de publicación.
        \item \textbf{SymPy:} Cálculo simbólico (álgebra, derivadas e integrales analíticas).
        \item \textbf{Pandas:} Manejo y estructuración de grandes volúmenes de datos experimentales.
    \end{itemize}

    \item Herramientas como \textbf{IPython} y las \textbf{Jupyter Notebooks} 
    permiten mezclar texto ejecutable, ecuaciones en \LaTeX, gráficos en tiempo real y 
    código interactivo.
\end{enumerate}

\section*{\textcolor{red}{\textit{Entornos virtuales}}}
	Antes de comenzar a trabajar con Python, es recomendable crear un entorno virtual para 
	el proyecto que deseamos realizar. Un entorno virtual es una copia aislada de Python 
    dentro de un proyecto que permite instalar librerías sin afectar al Python del sistema. 
	El entorno virtual permite aislar las dependencias y librerías 
	necesarias para cada proyecto, evitando conflictos con otras instalaciones de Python 
	en el sistema. Además, facilita la gestión de versiones y la reproducibilidad del entorno de 
	desarrollo. 
    
    Para crear un entorno virtual, se ejecuta el siguiente comando  en la terminal:
	%
\begin{lstlisting}
python3 -m venv .venv  
\end{lstlisting}
	%
	\lstinline|python3| usa el intérprete Python 3 instalado en el sistema. 
	El comando \lstinline|-m venv| indica que se desea crear un entorno 
	virtual, y \lstinline|.venv| es el nombre del directorio donde se 
	almacenará el entorno virtual (el . al inicio indica que es 
	un directorio oculto). Confirmamos que quedó instalado el entorno 
	virtual con el comando \lstinline|ls -la|.
	Ingresamos al directorio \lstinline|cd .venv/| y ejecutamos el comando \lstinline|ls -la| 
	para ver su contenido. Allí encontrarás los directorios \lstinline|bin|, \lstinline|include|, 
	\lstinline|lib| y el archivo \lstinline|pyvenv.cfg|. En \lstinline|bin| se encuentran los ejecutables 
	de Python y pip, en \lstinline|lib|se almacenan las librerías instaladas y se muestra la 
	versión de Python utilizada. En \lstinline|include| se encuentran los archivos de cabecera de Python 
	y el archivo \lstinline|pyvenv.cfg| contiene la configuración del entorno virtual.

	Una vez creado el entorno virtual, es necesario activarlo para poder utilizarlo.
	Se ejecuta el siguiente comando en la terminal:
	%
\begin{lstlisting}
source .venv/bin/activate
\end{lstlisting}
	%
	Note que el prompt de la terminal cambia, indicando que el entorno virtual está activo.
	Una vez activo el entorno virtual, se pueden instalar las librerías necesarias para el proyecto
	utilizando pip.
	%
\begin{lstlisting}
pip install --upgrade pip
pip install numpy scipy matplotlib sympy  pandas jupyter tqdm
\end{lstlisting}
	%
	Luego guardamos las dependencias del proyecto en un archivo \lstinline|requirements.txt| 
	con el comando: \lstinline|pip freeze > requirements.txt|. Si queremos recrear el entorno 
	en otra máquina, podemos instalar las dependencias desde el archivo 
	\lstinline|requirements.txt| con el comando: \lstinline|pip install -r requirements.txt|
	Para desactivar el entorno virtual, se ejecuta el comando \lstinline|deactivate|.
	Para el eliniar el entorno virtual, se ejecuta el comando \lstinline|rm -rf .venv|.
	{\color{blue} Es importante no sincronizar el entorno virtual con el repositorio de git, 
	para ello se recomienda agregar el directorio \lstinline|.venv| al archivo \lstinline|.gitignore|.}

\begin{cajaflex}[No usar sudo]
    Dentro del entorno, nunca es necesario usar privilegios de root.
\end{cajaflex}

\subsection*{\textcolor{blue}{Precedencia de Operadores}}

Al evaluar expresiones matemáticas, Python sigue el orden estándar de las operaciones 
algebraicas (jerarquía de operaciones). Las operaciones de igual jerarquía (como suma y resta) 
se evalúan de izquierda a derecha:
\[
1 - (2 + 3) = 1 - 5 = -4 \quad \text{frente a} \quad 1 - 2 + 3 = -1 + 3 = 2
\]

Sin embargo, la multiplicación (\texttt{*}) y la división (\texttt{/}) tienen mayor 
precedencia que la suma (\texttt{+}) y la resta (\texttt{-}). 
Para alterar el orden natural de evaluación deben utilizarse paréntesis \texttt{()}:

\begin{lstlisting}
In [1]: 2 * 5 + 3
Out[1]: 13

In [2]: 2 + 5 * 3
Out[2]: 17

In [3]: (2 + 5) * 3
Out[3]: 21
\end{lstlisting}

\subsubsection*{Resumen de jerarquía (de mayor a menor prioridad):}

\begin{enumerate}[leftmargin=*]
    \item \textbf{Paréntesis \texttt{()}:} Rompen la jerarquía por defecto.
    \item \textbf{Potenciación \texttt{**}:} Se evalúa de \textbf{derecha a izquierda} ($2^{3^2} = 2^9$).
    \item \textbf{Multiplicación \texttt{*}, División \texttt{/}, División entera \texttt{//} y Módulo \texttt{\%}:} Evaluadas de izquierda a derecha.
    \item \textbf{Suma \texttt{+} y Resta \texttt{-}:} Mención de menor prioridad, evaluadas de izquierda a derecha.
\end{enumerate}

\begin{lstlisting}
In [4]: 2 ** 3 ** 2    # Equivale a 2**(3**2) = 2**9
Out[4]: 512

In [5]: (2 ** 3) ** 2  # Fuerzado con parentesis = 8**2
Out[5]: 64
\end{lstlisting}

Para mostrar resultados en pantalla se utiliza la función \texttt{print()}. 
En física es común trabajar con cantidades muy grandes o muy pequeñas, por lo que Python 
permite definir números directamente en notación científica utilizando la letra \texttt{e} 
(o \texttt{E}) para representar la potencia de 10. Por ejemplo, definamos la velocidad de la luz en 
el vacío $c \approx 2.99792458 \times 10^8 \text{ m/s}$:

\begin{lstlisting}
In [31]: c = 2.99792458e8  # m/s

In [32]: print(c)
299792458.0

In [33]: print("La velocidad de la luz en el vacío es:", c, "m/s")
La velocidad de la luz en el vacío es: 299792458.0 m/s
\end{lstlisting}

La forma moderna y recomendada en Python para combinar texto y variables es 
mediante las \textbf{\textit{f-strings}} (anteponiendo la letra \texttt{f} antes de las comillas).
Esto, permite evaluar variables y expresiones directamente dentro de llaves \texttt{\{\}}. Es decir,
todo lo pongas dentro de las llaves \texttt{\{\}} es reconocido como código por python.

\begin{lstlisting}
In [34]: print(f"La velocidad de la luz es c = {c} m/s")
La velocidad de la luz es c = 299792458.0 m/s
\end{lstlisting}

Además, podemos aplicar especificadores de formato dentro de la llave utilizando dos puntos \texttt{:}

\begin{lstlisting}
# Formato en notacion cientifica con 2 decimales (:.2e)
In [35]: print(f"Notacion cientifica: c = {c:.2e} m/s")
Notacion cientifica: c = 3.00e+08 m/s

In [54]:  print(f"Notacion cientifica: c = {c:.2E} m/s")
Notacion cientifica: c = 3.00E+08 m/s

In [57]:  print(f"Notacion cientifica: c = {c:.3E} m/s")
Notacion cientifica: c = 2.998E+08 m/s

# Formato en punto flotante con 2 decimales (:.2f)
In [36]: print(f"Notacion flotante: c = {c:.2f} m/s")
Notacion flotante: c = 299792458.00 m/s

# Formato con separadores de miles y 2 decimales (:,.2f)
In [37]: print(f"Con separadores: c = {c:,.2f} m/s")
Con separadores: c = 299,792,458.00 m/s
\end{lstlisting}

Dentro de las llaves no solo va el nombre de las variables que queremos mostrar, 
también podemos hacer operaciones 

\begin{lstlisting}
In [4]: print(f"El doble de c es {2 * c} m/s")
El doble de c es 599580000.0 m/s

In [5]: print(f"La luz recorre {c / 1000} km en un segundo")
La luz recorre 299790.0 km en un segundo
\end{lstlisting}

También puedes usar cadenas

\begin{lstlisting}
In [6]: materia = "física computacional"

In [7]: print(f"Bienvenidos a {materia.upper()}")
Bienvenidos a FÍSICA COMPUTACIONAL
\end{lstlisting}

\subsection*{\textcolor{blue}{Importación de módulos}}

Las funciones predeterminadas en Python son limitadas. Por ejemplo, por defecto no podemos 
calcular razones trigonométricas (como seno o coseno), logaritmos ni raíces cuadradas. 
Para ello existen los \textbf{módulos} (o librerías), los cuales no se cargan por defecto en 
memoria para optimizar recursos.

El módulo estándar para operaciones matemáticas es \textit{math}. Existen varias formas de importarlo:

\begin{enumerate}
    \item \textbf{Importación específica:} \lstinline|from math import sin| \\
    Importa solo la función solicitada. Puede resultar engorroso si necesitamos usar decenas 
    de funciones distintas.

    \item \textbf{Importación masiva (no recomendada):} \lstinline|from math import *| \\
    Importa todas las funciones del módulo. El problema de esta práctica 
    (llamada \textit{contaminación del espacio de nombres}) es que si previamente habíamos 
    definido una variable llamada \texttt{sin}, el módulo la sobrescribirá sin advertencia.

    \item \textbf{Importación mediante espacio de nombres (recomendada):} \\
    Es preferible usar \lstinline|import math| o asignarle un alias corto como 
    \lstinline|import math as mate|.
\end{enumerate}

De esta forma, las funciones se invocan de manera segura usando la notación de punto. 
Note que los ángulos deben ingresarse siempre en radianes:

\begin{lstlisting}
In [38]: import math

# Pasar 90 grados a radianes: (90 * pi / 180)
In [39]: math.sin(90 * math.pi / 180)
Out[39]: 1.0

In [40]: import math as mate

In [41]: mate.sin(mate.pi / 2)
Out[41]: 1.0

# Tambien se puede usar la funcion integrada math.radians():
In [42]: math.sin(math.radians(90))
Out[42]: 1.0
\end{lstlisting}

\subsection*{\textcolor{blue}{Representación y límites del Número de Máquina}}

Como vimos en las clases pasadas, es crucial entender que las computadoras no trabajan con 
números reales arbitrarios, sino con una aproximación finita, \textit{puntos flotantes} 
(estándar IEEE 754 de 64 bits). 
Podemos inspeccionar los límites físicos de representación numérica de nuestro procesador 
directamente en IPython:

\begin{lstlisting}
In [10]: import sys

In [11]: sys.float_info.epsilon  # Precision de maquina (\epsilon_mach)
Out[11]: 2.220446049250313e-16

In [12]: sys.float_info.max      # Límite de desbordamiento (Overflow)
Out[12]: 1.7976931348623157e+308

In [13]: sys.float_info.min      # Límite de subdesbordamiento (Underflow)
Out[13]: 2.220446049250313e-308
\end{lstlisting}

\begin{itemize}
    \item \textbf{Precisión de máquina ($\epsilon_{mach} \approx 2.22 \times 10^{-16}$):} 
    Es la distancia entre el número $1.0$ y el siguiente flotante representable. Determina que en precisión doble tenemos aproximadamente $15$ a $17$ dígitos decimales de precisión.
    \item \textbf{Efectos prácticos:} Operaciones como $1.0 + 10^{-16}$ 
    resultarán exactamente en $1.0$ en la máquina debido a la pérdida de significancia.
\end{itemize}
